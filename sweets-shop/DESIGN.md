# BAKEBAKE(ばけばけ) ― 原宿発・変化するスイーツ専門店

## 1. コンセプト

原宿・竹下通りで一番大きいTikTokバズを生んでいるスイーツ店、という設定。
軸となるフックは「バズる」の理由を **見た目が変わる=化ける** という一点に絞ること。
色が変わるドリンク、割ると溶岩のように溢れるチーズタルト、ドライアイスの煙で
登場するパルフェ、引っ張ると伸びるもちドッグ ―― どれも「変化の瞬間」が
そのまま15秒の動画のフックになる、という一貫したブランドロジックを持たせる。

店名「BAKEBAKE」は日本語の「化ける(bakeru = 変身する)」と英語の「bake」を
掛けた造語。ロゴタイプはこの二重性(和と英、変身と製菓)を体現する軸になる。

タグライン: **「変わる、あふれる、消えていく。」**

## 2. デザインプラン(トークンシステム)

### カラー ― 白ベース + “変化”を示す2色のグラデーション

| トークン | HEX | 役割 |
|---|---|---|
| `--bg` | `#FFFFFF` | 基本背景。ユーザー指定の「白ベース」を素材そのものの質感として使う(製菓店の粉・生クリームの白) |
| `--surface` | `#FBF8FC` | カード等の面。白から極わずかに紫へ振った中間色で、ベタ塗りの単調さを避ける |
| `--ink` | `#18121F` | 本文色。純黒ではなく紫を帯びた黒にし、後述のアクセントと親和させる |
| `--ink-soft` | `#6E6478` | 補助テキスト、キャプション |
| `--before` | `#FF2D6F` | “変化前”を示す色。ホットピンク |
| `--after` | `#17D9C4` | “変化後”を示す色。ミント〜ティール |
| `--line` | `#ECE4F3` | 罫線・境界 |

アクセントは「ピンク→ティール」のグラデーション一本に絞り、ロゴ・CTA・
Before/Afterの状態表現だけに使う。他はすべて白と墨(ink)で構成し、
ブランドロジック(変化=フック)がそのまま配色ロジックになるようにする。

ダークモード(OS設定がdarkの場合)は `--bg` を `#120E18`、`--surface` を
`#1C1624` に反転し、ink/背景の関係を保ったまま同じグラデーションが
発光して見えるように調整する。ライト(白ベース)が既定表示。

### タイポグラフィ

- **ロゴ/英字ワードマーク**: 実行環境からGoogle Fonts CDNへの取得経路が
  ブロックされておりWebフォントのdata URI埋め込みができないため、
  代わりに「BAKEBAKE」のロゴタイプはSVG上でカスタムに描く扱いとし、
  文字そのものをグラデーション(ピンク→ティール)で塗り、極端に詰めた
  字間+わずかな波形ゆがみで“化ける”質感を出す。フォールバックの英字は
  system-ui の極太ウェイト(900)。クリシェ回避のためInter/Space Grotesk系
  は使わない。
- **日本語見出し・本文**: システムフォント
  (`"Hiragino Sans", "Yu Gothic UI", "Noto Sans JP", sans-serif`)。
  太字(900/700)を大胆に使い、ユーザー指定の「文字大きめ」に応じて
  本文ベース19px、見出しはclamp()で最大96px前後までスケールさせることで
  フォント調達なしでも十分な存在感を確保する。
- **キャプション/データ数値**: 同じsystem-uiスタックの900ウェイト +
  `font-variant-numeric: tabular-nums`(再生回数・価格などの桁揃え)。

### レイアウト

1カラムの縦スクロール構成。白い余白を製菓店の「粉をふるった台」に見立て、
各セクションの主役(ロゴ、Before/Afterカード、数値)だけを大胆に置く。
ヒーローは中央にUnboundedの巨大ロゴ+Canvasで描く「変化するブロブ」を
モーフィングさせ、以降のセクションはBefore→Afterのグラデーションを
共通言語として使い回す(ホバー/タップで色が変わるメニューカード、
再生数チップ、フッターのロゴ発光)。

## 3. プランの検証(汎用パターンの排除)

- ❌ 初期案: 生成AIにありがちな「紫→青グラデーションのヒーロー」を
  そのまま使いそうになった → ✅ 修正: グラデーションを
  ピンク→ティールの「Before/After」という意味を持つ2色に限定し、
  かつ使用箇所をロゴ・CTA・状態表現のみに絞ることで、
  装飾ではなく情報(変化の表現)として機能させた。
- ❌ 初期案: 角丸カード+アクセントバーという量産パターンに寄りかかりそうに
  なった → ✅ 修正: カードは角丸を弱め、代わりに「Before状態のピンク文字」
  と「After状態のティール文字」がホバーで入れ替わるインタラクションを
  主役にし、装飾ではなく機能(変化の疑似体験)でカードを差別化。
- ❌ 初期案: 絵文字をセクション見出しの飾りに使いかけた → ✅ 修正:
  絵文字を廃し、代わりにUnboundedの巨大な英数字ラベル
  (01 SODA / 02 TART...ではなく商品名そのものを主役に)で階層を作る。

## 4. セクション構成(Claude Codeでの実装単位)

1. Hero ― ロゴ、タグライン、Canvasブロブモーフィング、CTA2種
2. Concept ― 「なぜ、ばける?」3原則(変わる/あふれる/消える)
3. Signature Menu ― 5品のBefore/Afterカード(ホバーで状態が変化)
4. Buzz ― 再生数・ハッシュタグなど数値訴求ストリップ
5. Gallery ― CSS/SVGで描くドリップ/ブロブのビジュアルグリッド
6. Access ― 住所・営業時間・行き方(すべて架空設定として明記)
7. Footer ― ロゴ、ナビ、コピーライト

## 5. 実装メモ

- 完全自己完結の単一HTML(`index.html`)。外部フォント/画像CDNは使用しない。
- 写真素材がないため、すべてのビジュアルはCSS gradient / SVG / Canvasで
  「ドリップ」「湯気」「色変化」を表現する抽象イラストとして構築する。
  実在の写真・実在店舗のレビューを装った引用は一切使用しない(架空店舗)。
- prefers-reduced-motion 時はブロブモーフィング・湯気アニメーションを停止。
